## MODIFIED Requirements

### Requirement: Selective monthly recalculation

The system SHALL recalculate only months for which new data was incorporated during that same run. For each month selected for recalculation, the system SHALL use all existing daily CSV files in that month as input. Only `acumulado-marca-modelo-provincia.csv` SHALL be recalculated for the affected months.

(Previously: recalculated all three monthly aggregates — `acumulado-marca-modelo.csv`, `acumulado-marca.csv`, and `acumulado-marca-modelo-provincia.csv` — together.)

#### Scenario: Month with new data

- WHEN at least one new day from a specific month is downloaded and processed in the run
- THEN `acumulado-marca-modelo-provincia.csv` for that month is recalculated
- AND the recalculation reads every existing daily file `/microdatos-etl/data/YYYY/MM/DD.csv` for that month

#### Scenario: Month without new data

- WHEN there are no new days for a specific month in the run
- THEN no monthly CSVs are recalculated

## MODIFIED Requirements

### Requirement: Monthly aggregation by brand, model and province

The system SHALL maintain a monthly CSV with accumulated counts for `MARCA_ITV`, `MODELO_ITV`, and `PROVINCIA_VEH` combinations.
The monthly output SHALL be stored at `/microdatos-etl/data/YYYY/MM/acumulado-marca-modelo-provincia.csv`.
It SHALL be the only monthly aggregate CSV generated by the ETL.

(Previously: stated it was generated in the same operation as `acumulado-marca-modelo.csv`. That reference is removed.)

#### Scenario: Monthly aggregation structure

- WHEN the monthly province CSV is generated
- THEN it includes columns `MARCA_ITV,MODELO_ITV,PROVINCIA_VEH,COMUNIDAD_AUTONOMA,CILINDRADA_ITV,COUNT`
- AND each row represents a unique `MARCA_ITV` + `MODELO_ITV` + `PROVINCIA_VEH` combination
- AND `COUNT` is the total number of records in that month for that combination
- AND `CILINDRADA_ITV` is the validated displacement value for that brand-model combination

#### Scenario: Monthly aggregation ordering

- WHEN the monthly province CSV is written
- THEN rows are sorted alphabetically by `MARCA_ITV`
- AND in case of ties, by `MODELO_ITV`
- AND in case of ties, by `PROVINCIA_VEH`

# Delta for microdatos-etl-shared-lib

## MODIFIED Requirements

### Requirement: aggregate.js exports writeAggregates and path helpers

`lib/aggregate.js` SHALL export:
- `monthDir(year, month)`: returns the absolute directory path for a given year and month.
- `provinciaMonthlyPath(year, month)`: returns the absolute path to `acumulado-marca-modelo-provincia.csv`.
- `writeAggregates(year, month, rows)`: accepts an array of row objects and writes only the province-level monthly aggregate CSV for the given year/month, applying cilindrada consistency validation.

(Previously: exported `monthlyPath()` for `acumulado-marca-modelo.csv` and `brandMonthlyPath()` for `acumulado-marca.csv`, and `writeAggregates` produced all three CSVs.)

#### Scenario: monthlyPath no longer exported (REMOVED)

- ~~WHEN `monthlyPath('2026', '03')` is called~~ → deleted
- ~~THEN it returns the absolute path ending in `microdatos-etl/data/2026/03/acumulado-marca-modelo.csv`~~ → deleted

#### Scenario: writeAggregates produces only provincia CSV

- WHEN `writeAggregates(year, month, rows)` is called with a non-empty rows array
- THEN only `acumulado-marca-modelo-provincia.csv` is written to the correct month directory

#### Scenario: writeAggregates logs warning on cilindrada conflict

- WHEN two rows for the same brand+model combination have different `CILINDRADA_ITV` values
- THEN a warning is printed to stderr with the brand, model, all values, and the chosen (most frequent) value
- AND the most frequent value is used in the output CSV
